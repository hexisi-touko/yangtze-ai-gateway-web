## 更新日志维护

网页入口：管理端左侧“管理端更新日志”，地址 `/admin-updates`，仅管理员可读。
版本数据：`pkg/adminversion/versions.json`，随后端源码构建，前端不会冒充旧后端的最新版本。
每版记录：版本、日期、发布状态、业务变化、技术交接和已知限制。客户端发布继续使用现有“客户端版本”模块。

修改清单后执行：

```sh
node scripts/generate-admin-changelog.mjs
node scripts/generate-admin-changelog.mjs --check
```

生成的 `docs/ADMIN_CHANGELOG.md` 方便不登录系统的同学查看，网页和文件使用同一份数据。
本地通过不等于正式部署成功；正式发布时间应在之后云端验收完成时记录。不要改写已发布标签。
构建时可用 Go ldflags 写入 `pkg/adminversion.Revision`、`pkg/adminversion.BuildTime`；未写入时界面显示本地构建状态，不伪造提交或部署时间。

## 月度正文与旧数据

月度归档把实际采集的成员输入保存为每成员 gzip JSONL 文件，报告保存文件清单、记录数和校验值。
管理员可分别导出每个成员的 HTML 文档；浏览器直接打开，可按日期阅读或打印。所有文字经过 HTML 转义，不执行成员提交的代码。
导出采用文件流，超过 64 KB 的单条内容、超过 1000 条的月度记录仍可处理。北京时间用于归档和日期标注。
成员每日请求通过分页查看，筛选限定成员和起止时间。系统/开发者提示及已识别的内部代理消息不作为成员正文展示。正常英文、中文和代码都保留，不按语言删内容。

默认正文不截断。`MEMBER_REQUEST_CONTENT_MAX_BYTES` 设置为正数时才启用长度限制；历史已截断内容会显示提示，不能恢复未保存的部分。
旧报告可“补建正文归档”，只能补建当时数据库中仍存在的内容。系统未采集、绕过本网关的内容以及已经删除的正文无法恢复。AI 回复不在本次采集范围内。

`MEMBER_REQUEST_ARCHIVE_DIR` 指定正文文件的持久化目录；默认 `./member-request-archives`。
当前生产 Dockerfile 工作目录为 `/data`，必须持续挂载 `/data`，并将数据库和正文目录一起备份。
本地工作目录在 E 盘，所以新生成的归档和导出临时文件也在 E 盘。导出临时文件完成后删除。
文件校验通过且原始记录边界一致才允许现有清理任务删除在线正文。文件缺失、损坏或出现晚到记录时停止清理，不丢新增正文。
压缩正文档案本身不会被这次修改自动删除；保留在线摘要和压缩档案不同于永久释放全部历史数据空间。
多个进程同时补建时使用数据库条件更新避免覆盖已完成归档；多个归档副本必须共享持久化目录。

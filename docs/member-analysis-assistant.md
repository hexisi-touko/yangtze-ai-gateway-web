# 管理员 AI 分析助手

入口：管理员 → 成员使用分析 → AI 助手。

## 接入

1. 在“分析服务”填写已获授权的外部服务 API 基础地址、模型 ID、专用 API Key。
2. 第一版支持 OpenAI 兼容 Chat Completions：例如基础地址 `https://api.example.com/v1`，后端请求 `/v1/chat/completions`。不是 ChatGPT 网页登录，也不是仅支持 Responses 的接口。
3. 保存后点击“测试连接”。只发送固定测试问题，不发送成员数据；测试也可能由服务商计费。
4. 选择日期（最多 31 天）和成员，生成数据预览，确认授权发送，再提问。
5. 可继续追问；每次成功结果保存到“分析记录”，可重新打开。每个管理员只能读取自己创建的分析记录。

## 数据边界

- 数据预览只是本地数据库快照，不会触发外部调用；后续分析使用同一快照，不会悄悄改成最新日志。
- 日期按页面浏览器时区转换为时间戳，区间为左闭右开；项目数据只包含区间内开始的上报会话，不表示期间所有在做的项目。
- 发送成员编号、成员类型、调用统计、模型名、统计信号，以及匿名项目分组及上报时间。
- 不自动发送姓名、登录名、真实项目名、本机路径、分支、用途自由文本、请求/响应原文、源码、IP、任何渠道或成员密钥。
- 管理员输入的问题和本次已有问答也会发给外部服务；不要手动粘贴敏感数据。匿名化仍不等于绝对不可识别，需要项目组授权和合适的数据处理政策。
- 项目上报不等于实际工时，也不能证明调用属于该项目。提示词禁止用 Token 数自动评绩效或把高频调用断言成滥用。结果需人工复核。

## 安全与费用

- 全部接口要求 AdminAuth，不提供给 EXE 或普通成员。
- Key 只交给后端，GET 接口仅返回 `has_key`，不返回原值；前端不写 localStorage。留空保留旧 Key，改变基础地址必须提供新 Key。
- Key 与现有渠道 Key 一样存储于受限数据库中，本功能没有实现数据库字段加密。数据库、备份、导出文件必须限制访问，不能作为源码上传。配置放在独立表，不经过通用 Option 查询接口。
- 仅 HTTPS 公网 443，拒绝私网/回环/元数据地址、跳转和不受信任 TLS；不继承中转通道的关闭证书验证选项，也不走环境代理。
- 独立直连，不调用本站中转计费链路，不扣成员额度；由分析 Key 的账号承担费用。建议在服务商侧设置独立 Key 的预算。
- 手动触发，没有自动定时任务、自动重试或自动限额处罚。单次最多输出 2000 Tokens，超时 60 秒；每进程最多同时两次分析，每个对话最多 6 轮，数据快照最多 48 KB、项目会话最多 500 条。HTTP 响应最多 256 KB。
- 已成功的问答和预览保存在数据库；失败不会写入假答案。网络断开时可能产生服务端已计费但本地未保存的情况，不自动重试。
- 第一版没有自动清理历史；按项目组要求制定保留期限后再加清理任务。保存分析记录不会删除原始使用日志。

## 部署与接口

所有改动位于源码仓库，不依赖当前 Windows 绝对路径。GoLand 重新运行后端后，GORM 自动增加 `member_analysis_configs`、`member_analysis_runs` 两张表（SQLite/MySQL/PostgreSQL）。云端从同一源码构建部署，外部服务配置通过管理员页重新填写或随受保护的数据库迁移。

接口前缀 `/api/member-usage/ai`：

- `GET/PUT /config`：读取安全配置、保存或移除密钥。
- `POST /test`：无成员数据连接测试。
- `POST /preview`：`start`、`end`、`member_id`（0 为全部），返回本地快照 ID。
- `POST /chat`：`parent_id`、`question`、`consent: true`、`config_version`；返回新分析记录。
- `GET /history`：当前管理员最近 50 个成功分析回合。
- `GET /history/:id`：当前管理员自己的快照和对话。

不需要把 EXE 重打包。前端变更可由开发服务器热更新；后端必须在 GoLand 重新运行，旧进程不会自动加载新增接口。

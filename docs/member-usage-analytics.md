# 成员使用分析：第一版本地开发与部署

## 边界

- 使用日志：保留原始消费、错误、退款、登录等记录，用于逐条排查。
- 任务日志：保持已有绘图、视频等异步生成任务含义，不当成员工工作日志。
- 成员使用分析：新增管理员入口，汇总用量、人工登记的当前项目和用途、待关注信号、周期快照。普通成员不可访问 API。
- 实习生、全职人员是独立业务字段，不改变用户角色、额度、令牌、上游调度或调用权限。
- 不采集提示词正文、不向外部模型发送成员数据、不自动判断违规、不自动评分。此版本不包含 AI 用途分类、自动周期任务或人工核查工作流。

## 统计口径

1. 时间区间为 [start, end)，页面按浏览器本地自然日选择，最多 31 天。仅统计已保存的 type=2/5/6 日志；登录不计入调用。
2. 消费记录不等于独立请求，也不等于完整响应成功。补扣费、重试、异步任务结算等可能增加记录。没有用这些记录计算“成功率”。
3. Tokens 为消费日志中 prompt_tokens + completion_tokens。扣费与退款分别求和，单位为原始 quota，不是人民币；退款可能对应区间之前的调用，不能简单视作本期成果或损耗。
4. 活跃成员有消费或错误记录。无调用的成员仍显示，零用量不显示为 100% 成功。
5. 单分钟峰值是自然分钟内消费和错误记录数，不是并发数。达到 30 条只触发人工核查提示。
6. 错误记录至少 5 条且占消费与错误记录总数至少 20% 时提示。流中断可能仍记为消费，所以不是所有失败都在错误记录中。
7. 有调用但当前项目或用途为空时提示补充。当前用途是管理员填写的成员级资料，不是请求级分类、密钥绑定或历史用途证明。改变资料会影响未归档历史查询；已归档快照不受影响。
8. 已删除成员的历史消费仍计入并标为已删除，不能再编辑其资料。已清理、关闭记录或上游未提供的数据不可恢复。
9. 单次查询上限 50000 条记录、5000 个现存成员，查询超时 20 秒。超限返回错误而不是静默截断。生产日志增加后需要改为分页聚合或汇总表。

## 数据和接口

新增主数据库表 member_usage_profiles、member_usage_reports。两套迁移入口均已注册，后端按原有迁移流程建立新表，不改旧日志表；日志可以来自独立 LOG_DB，无跨库 JOIN。

- GET /api/member-usage/summary?start=秒级时间戳&end=秒级时间戳
- PUT /api/member-usage/profiles/:user_id：member_type、project、purpose
- GET /api/member-usage/reports：最近 100 份，不返回快照正文
- POST /api/member-usage/reports：title、note、start_time、end_time
- GET /api/member-usage/reports/:id：查看与导出持久化快照

所有接口经过 AdminAuth；写操作沿用现有管理员审计。用途属于共享管理员资料，当前采用最后一次保存生效，避免多人同时编辑同一成员。

归档以服务端重新查询的全体成员统计为准，不受页面搜索、成员类型筛选影响。保存时固定统计、当时资料、操作者与人工总结。没有修改、删除或自动清理接口；纠正报告需创建新报告。归档不删除原始日志，也不能替代完整数据库备份。导出文件含成员信息，应限制共享。

## 本地查看

在当前工作分支开发。GoLand 使用项目已有的 New API Backend (GoLand) 配置，后端代码修改后点击重新运行；前端开发服务运行时会自动更新。

- 前端 /member-usage，当前本地前端端口 5173。
- 后端端口 3000。新接口返回 404 时先查看浏览器 Network 的响应来源，再对照 GoLand 请求日志；不能仅凭状态码断定运行了旧后端。
- 用现有管理员账号登录。没有真实消费时显示 0；不往本地业务数据库灌入演示记录。

### 2026-09-05 缓存故障修复

浏览器实际请求 `/api/member-usage/summary` 返回 `404 Not Found (从磁盘缓存)`，旧响应含 `Cache-Control: max-age=604800`。未匹配的 API 曾进入网页兜底的缓存中间件，被缓存一周；后端更新后，请求仍可能不离开浏览器，因此 GoLand 没有对应请求日志。

- 前端统一 API 请求添加 `no-cache, no-store`，既重新验证旧缓存，也不保存新响应。只有 `no-store` 不能保证绕开已有缓存。
- 后端网页兜底不再缓存 `/api`、`/v1` 的错误响应；成员分析路由在鉴权前使用现有 `DisableCache` 中间件。
- GoLand 工作目录下的 `.env` 应配置固定随机 `SESSION_SECRET`，并保持 Git 忽略。缺失时每次进程启动随机生成，旧登录及刷新令牌会失效。不要把开发密钥复制到云服务器或提交仓库。
- 修复时已在实际浏览器看到 5 个账户及其中零调用账户，合计 3 条消费记录、58 Tokens，并打开了成员类型、当前项目、登记用途编辑窗口。这是本地已有数据，不是新增演示数据。
- 保存与失败保留输入的前端测试、资料保存及归档快照的隔离数据库测试已通过；没有替真实成员填写项目或用途。重启后若旧登录失效，需要用原管理员账号重新登录。

## 合并和服务器部署

1. 提交本次 model、service、controller、router、web 和本文档修改；不要提交数据库、日志、个人 IDE 配置、密码、令牌、node_modules 或本地测试产物。
2. 合并到团队约定的部署分支前执行后端测试、前端 typecheck、相关 vitest、lint 和生产 build。
3. 部署前备份主数据库和独立日志库，验证可恢复；保留上一个自建镜像标签。数据卷继续使用原有卷，不执行 docker compose down -v。
4. 必须从合并后的完整源码构建现有 Dockerfile，例如 docker build -t yangtzeapi:member-usage-v1 .。现有 docker-compose.yml 中默认的 calciumion/new-api:latest 是官方镜像，不含本功能。实际部署文件应使用团队构建的镜像标签或私有镜像仓库标签。
5. 只替换 New API 应用服务镜像，不重建数据库/Redis 数据，不改变 CPA、上游账号和密钥。前后端一起更新；前端 production build 会打入镜像，服务器不需要运行 5173 开发服务。
6. 沿用服务器自己的 SQL_DSN、LOG_SQL_DSN、Redis、HTTPS、安全入口和持久卷配置；不要复制本地 HTTP/密码配置。后台的日志采集开关和日志保留期也会影响统计完整性。
7. 首次启动由现有迁移流程建表，确认迁移日志无错误；若禁用了自动迁移，按团队已有迁移流程先创建新表。
8. 验收：管理员可打开页面、非管理员被拒绝；用途保存后刷新仍存在；归档可查看和导出；旧使用日志、任务日志和正常调用不受影响。
9. 回退只切回原镜像标签，保留新增表和数据，勿用删库/删卷回退。更广的跨版本迁移风险需结合团队其他合并内容评估。

当前不新增对象存储、独立分析服务器或模型 API 采购要求。上线前应约定成员知情范围、报告访问权限、保留时长和人工复核责任；不要以 Token 用量作为唯一 KPI。
